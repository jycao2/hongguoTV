# 小爱同学语音开播（巴法云中转）

电视端从 `0.28.15-xiaoai` 起内置这条链路，**不需要 NAS、不需要 Home Assistant、不需要改路由器**。

```
小爱音箱 → 米家（我的 → 其他平台设备 → 巴法）→ 巴法云 → 电视（每 2 秒拉一次主题列表）
```

## 为什么是巴法云

小爱只会说「打开 X / 关闭 X」，它不会把一句话原样传出来，米家也不允许第三方 App 把自己塞进去当设备。
米家原生支持绑定**巴法云账号**，绑完以后巴法里的主题会以「设备」的身份出现在米家，小爱就能直接喊它的名字。
这是目前唯一既不要企业资质、又不用加硬件的一条路。

于是约定：**一个主题 = 一个动作，主题昵称 = 小爱要喊的名字**。

## 一次配置（10 分钟）

1. **注册巴法云**：<https://cloud.bemfa.com> —— 用**手机号或邮箱**注册，别用微信扫码（扫码注册的账号接不了米家）。
2. **拿私钥**：登录后控制台首页那串 32 位十六进制，就是私钥（本文里的事都靠它）。

   > 它既是 MQTT 的 clientID，也代表账号，只存在电视本机；界面里只显示 `前4…后4`。
3. **建主题**：让每部想看的剧、每个想跳的模块各占一个主题。

   | 主题名 | 昵称（小爱喊的就是它） | 效果 |
   |---|---|---|
   | `hgplay1...001` | `黄石第五季` | 按名字搜并起播（有进度就续播） |
   | `hgplay2...001` | `文盲修仙` | 同上，另一部 |
   | `hgmod1...001` | `红果片源` | 跳到片源模块 |
   | `hgmod2...001` | `红果首页` | 回到首页 |

   规则：
   - **主题名只能用字母数字**，且必须以 `hg` 开头（电视只认这个前缀，免得把你别的巴法设备当成指令）；
   - **末三位是设备类型**：`001` 插座、`002` 灯泡、`006` 开关…… 不写后缀的主题不会同步到米家，`001` 最稳；
   - 昵称可以随便写中文，进主题的「更多设置」里改。
4. **同步到米家**：米家 App → 我的 → 其他平台设备 → 右上角添加 → 找到「巴法」→ 登录同一账号。
   这些设备只出现在「其他平台设备 → 巴法」里，不会进米家首页，这是正常的。
5. **电视上填私钥**：设置 → 设备与数据 → 小爱同学 → 扫码填写（用手机输入，不用遥控器敲 32 位）。
   状态显示「已连接 · N 个设备」就成了。

之后直接说：**「小爱同学，打开黄石第五季」**。

## 容易卡住的地方

- **巴法 App 里的「+ / 添加设备」不是这个入口**：那是最配网（输 WiFi 密码、搜硬件），没有实体硬件会一直卡在搜索。
  主题只能在**网页控制台**建：<https://cloud.bemfa.com> → MQTT 设备云 → 添加设备 → 选「自定义主题」→ 填主题名。
- **主题名的末三位决定米家里的身份**：`001` 插座、`002` 灯泡、`006` 开关。不带后缀的主题不会同步到米家，所以统一用 `001`。
- **改昵称**：控制台主题行右侧「更多设置」→ 昵称，保存即可；改完要去米家点一次「同步设备」。
- 先建**一个**主题测通再批量加，别一上来建十个（免费版有主题数上限）。

## 昵称怎么解析

先剥掉 `红果` / `红果TV` / `hongguo` 前缀和两端的装饰符，再看剩下的：

- 正好是模块名 → 跳模块：`首页`、`搜索`、`排行榜`、`收藏`、`最近观看`、`片源`、`本地库`、`设置`
- 其它（两个字以上）→ 当剧名去搜
- 只有一个字 → 不响应，避免「看」这种昵称乱触发

所以 `红果黄石第五季` 和 `黄石第五季` 等价；`红果片源` 跳模块，`片源` 也一样。

## 边界

- **电视上的红果TV要在前台**：轮询只在 Activity 可见时跑（`onStop` 就停）。后台常驻会被系统掐，且费流量。
- **延迟 0–2 秒**：2 秒一轮，换来的是断网、待机、进程重启都不用重连状态机。
- **走云端**：小爱识别本来就在小米云，指令再经巴法云，整条链路出域。私钥泄露等于别人能遥控你的电视，别外传。
- **米家不能改名**：「其他平台设备」里设备名来自上游，要改名就回巴法控制台改昵称（再点一次同步）。
- **`watch` 找不到就只在电视上提示**，不会瞎播第一条。
- 想加一部新剧：巴法云加一个 `hgplayN001` 主题 + 改昵称 + 米家同步一次，不用动电视。

## 实现备忘（改这块代码前先看）

- **电视必须连一条 MQTT 长连接**（`bemfa.com:9501`，clientID = 私钥，订阅自己的 `hg` 主题）。
  米家下发指令前会先看设备在不在线，而巴法云的「在线」= 有客户端订阅了这个主题。只轮询 HTTP
  的电视永远算离线，小爱会直接回「设备不在线」——**指令根本不会发出来**，轮询再好也没用。
- **通配符订阅 `hg#` 会被拒**（SUBACK 返回 0x80），只能逐个订阅；新加主题要重新订阅，
  所以电视在线时每 60 秒还会拉一次列表刷新映射。
- **MQTT 的消息里只有主题名，没有昵称**，昵称得靠 `allTopic` 拉回来做映射。
- **`allTopic` 返回的主题数组在 `data.data` 里**，外面还包一层对象；文档写的是 `data` 直接是数组。
  两种都兼容，见 `XiaoAiVoice.parse`。
- **判「有新指令」靠 `msg == "on"` 且 `unix` 比上次新**。实测推送之后两者都会更新（msg 从空变 `on`，
  unix 跟着走），第一轮只记基线不执行，所以不会开机就自动播放。MQTT 与轮询双通道要去重，
  否则同一条指令会播两遍。
- **主站搜索对不认识的词不返回空，而是给一批热门推荐**，所以「一句话开播」拿到结果后必须过标题匹配
  （`TitleMatch`：完全相同 → 标题含关键词 → 关键词含标题），对不上就停在搜索页提示，绝不取首条硬播。
  这条是踩出来的：喊「黄石第五季」曾经播出过《1000集让我留下来了》。

## 和另外两条路的关系

| 方案 | 需要什么 | 自由度 |
|---|---|---|
| 巴法云（本文） | 只需小爱 + 电视 | 一个语音名 = 一个动作 |
| [`scripts/voice-bridge`](../../scripts/voice-bridge/README.md) | 一台常开的主机跑 Python | 一句话自由解析（「我想看…」「打开…」） |
| 中枢网关「虚拟事件」+ Home Assistant | 中枢网关 + 一台跑 HA 的主机 | 事件名可以带任意文本，最灵活 |

三条路都落到同两条遥控命令：`{"cmd":"watch","query":…}` 和 `{"cmd":"open","module":…}`。
