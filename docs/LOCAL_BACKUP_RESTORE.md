# 本地备份与自动恢复

> 状态：**已实现**（2026-10-18 初版方案，2026-10-19 补充场景并实现；已在 API 30 电视真机验证备份生成与恢复）。实现与本文冲突时以代码为准并回写本文。

## 1. 目标与范围

用户手动卸载应用后重新安装，希望**不走远程、不手动操作**即可恢复本机数据。现状是所有数据保存在应用私有目录，卸载即清空。

恢复的数据（复用 `LibraryBackup` 现有格式与上限）：

| 数据 | 上限 | 说明 |
| --- | --- | --- |
| 收藏 | 500 | 含封面、角标、标签 |
| 稍后看 | 100 | |
| 观看进度/历史 | 200 | 同剧保留 `updatedAt` 更新的一条 |
| 已看完标记 | 500 | 仅保留仍存在于收藏/历史中的 ID |
| 搜索记录 | 20 | |
| 收藏分组 | 500 条关联 | 分组名 ≤20 字 |
| 隐藏记录 | 500 | |
| 播放/弹幕设置 | — | 清晰度、倍速、自动连播、默认内容类型、画面模式、自动下一季、弹幕开关/不透明度/字号/速度/行数 |

不恢复：

- 首页 7 天缓存（重装后自动重新拉取）
- 主题、按剧片头片尾跳过（设备偏好，不在 `BackupData` 内）
- 收藏更新提示状态（`favoriteUpdates` 不在备份格式内）；恢复收藏后按现有逻辑重新检查更新

## 2. 平台与存储适配（按 Android 版本分支）

所有写入都必须经过统一的存储适配层，调用方不直接拼路径。

| 系统 | 备份写 | 恢复读 | 权限 |
| --- | --- | --- | --- |
| API 26–28 | 直接文件 `/sdcard/hongguotv/` | 直接文件 | 运行时 `WRITE_EXTERNAL_STORAGE`（同时覆盖读） |
| API 29 | 走 `MediaStore.Downloads`（`RELATIVE_PATH=hongguotv`，自有条目可写） | 先查自有 MediaStore 条目；读不到再申请 `READ_EXTERNAL_STORAGE` | 写入无需权限；读取可能需运行时权限 |
| API 30+ | 直接文件 `/sdcard/hongguotv/` | 直接文件 | `MANAGE_EXTERNAL_STORAGE`（`Environment.isExternalStorageManager()`） |

说明与约束：

- 应用 `targetSdk=36`，`requestLegacyExternalStorage` 在 API 29 上不可依赖，因此 API 29 使用 MediaStore 作为主路径；实现时先在真机验证自有条目在重装后能否直接读回，若不能则回退为申请 `READ_EXTERNAL_STORAGE`（API ≤32 有效）。
- `MANAGE_EXTERNAL_STORAGE` 属于敏感权限，本项目为侧载 TV 应用可接受；若未来上架应用商店需改为 MediaStore/SAF 方案。
- 部分厂商电视/盒子可能没有「所有文件访问」设置页：视为权限不可用，自动备份/恢复停用，设置页给出「使用手机备份迁移」的替代入口，不崩溃、不反复弹窗。
- 无公共存储（少数纯内嵌存储盒子）或目录只读：`canWrite=false` 时静默停用，与权限被拒同路径处理。
- 只使用主外部存储（`Environment.getExternalStorageDirectory()` / `MediaStore` 默认卷），不处理 SD 卡、U 盘等多卷场景。

## 3. 文件布局与原子写

- 固定目录 `/sdcard/hongguotv/`（API 29 对应 `Downloads/hongguotv/`）
- 固定文件：
  - `hongguotv-backup.json`：当前正式备份
  - `hongguotv-backup.prev.json`：上一份轮换副本
  - `hongguotv-backup.json.tmp`：写入中的临时文件
- 每次整体覆盖，不累积多份；只识别上述固定文件名，目录中用户放入的其他文件一律忽略。
- 序列化复用 [LibraryBackup.encode()](../kotlin-tv/core/src/main/kotlin/com/hongguotv/core/LibraryBackup.kt)（`format="hongguotv.library"`、`version=1`、≤2 MB），数据来自 `LibraryIndex.snapshot()`。

轮换写入顺序（每一步单独可中断）：

1. 写 `.tmp`，`flush + fsync` 成功
2. 删除旧的 `.prev`
3. 正式文件改名为 `.prev`（不存在则跳过）
4. `.tmp` 改名为正式文件

| 中断点 | 结果 | 恢复行为 |
| --- | --- | --- |
| 1 之前/期间 | 正式文件与 `.prev` 不变，仅残留 `.tmp` | 读正式文件；启动时清理 `.tmp` |
| 2 之后、3 之前 | 少一份旧副本 | 读正式文件 |
| 3 之后、4 之前 | 正式文件缺失，`.prev` 为完整旧数据 | 回落 `.prev` |
| 4 完成后 | 正常 | 读正式文件 |

- 所有写入在现有串行写队列线程执行（`Library` 的 `LatestWriteQueue`），不新增并发写入口。
- 读取时：先主文件，解码失败再 `.prev`，都失败按全新状态启动。

## 4. 备份触发与时机

| 触发 | 时机 | 说明 |
| --- | --- | --- |
| 数据变更 | 每次 `persist()` 落盘成功后 | 防抖 5 秒，连续操作只写一次 |
| 生命周期检查点 | `flush()`（切后台/退出） | 若有未落盘的变更则立即写 |
| 首次授权成功 | 权限从无到有 | 立即全量写一次，避免用户装好不动就没备份 |
| 启动补写 | 启动时已有权限、库非空、且备份缺失或超过 24 小时 | 后台异步写一次 |

必须遵守的守卫：

- **空库启动不写备份**：新装应用、本地库为空且存在有效备份时，恢复流程完成前不得写入，避免把待恢复的备份覆盖成空文件。
- 用户主动清空收藏/历史后，`persist()` 会置“脏”标记，此时允许写入空内容——备份必须反映用户的删除意图，卸载后不应把旧数据恢复回来。
- 启动补写只在库非空时执行；`flush()` 只在本进程发生过写操作（脏标记为 true）时执行。
- 写入前先做一次编码大小校验，超过 2 MB 不写并静默放弃（当前上限内几乎不可能触发）。
- 无权限、IO 异常、磁盘满、只读：全部静默跳过，不重试、不提示、不影响业务。

## 5. 恢复流程

触发条件（必须同时满足）：

1. 本地库为空（收藏、稍后看、历史/进度、搜索记录、分组全部为空；设置项有默认值不算“有数据”）
2. 存储可读，正式或 `.prev` 至少一份能成功解码
3. 用户未关闭「本地自动备份」开关
4. 本次安装尚未做过恢复决策（私有 prefs 记录 `restoreChecked=true`）

流程：

1. 首次启动检测备份 → 显示一行说明（「检测到本机备份，授权存储权限后自动恢复收藏与记录」）→ 申请权限
2. 授权成功 → 读主文件 → 失败读 `.prev` → `LibraryBackup.decode()` → `Library.restore(restoreSettings=true)`（与手机备份合并语义一致）
3. 恢复完成后写回一份备份并置 `restoreChecked=true`；刷新收藏、历史、搜索、设置界面（复用手机备份导入后的刷新路径）
4. 拒绝授权或无备份：置 `restoreChecked=true`，按全新状态启动，不重复询问
5. 本地库非空：永不自动恢复，直接置 `restoreChecked=true`

容错：

- 备份缺失、损坏、格式/版本不符、超过 2 MB：全部按全新状态启动，不崩溃、不弹错误
- 解码在内存中一次性完成后再合并，合并过程中失败不影响现有数据（空库场景下等价于全新启动）
- 恢复期间应用被杀死：下次启动库仍为空且 `restoreChecked` 未写入，可重新走一次恢复（幂等）

## 6. 权限与 UX

- 首次启动只在“本地库为空”时申请一次；被拒后记录标记，**之后不再自动弹权限请求**
- 设置页新增「本地备份与恢复」入口，展示状态：
  - `未授权`：按钮「授权并立即备份」
  - `已启用`：显示「上次备份：MM-dd HH:mm」与「立即备份」
  - `已关闭`：自动备份开关关闭时的状态说明
  - `不可用`：设备无公共存储或厂商无权限入口，提示改用手机备份
- 设置页提供「本地自动备份」开关（默认开，仅本机偏好，不写入备份文件）；关闭后既不写也不再自动恢复，用户可随时重新打开
- API 30+ 按钮跳系统「所有文件访问」设置页；API 26–29 走标准运行时权限弹窗
- 授权成功立即补写一次；授权被拒可从设置页反复手动触发，但系统级「拒绝且不再询问」时引导去系统设置
- 与「手机备份与恢复」并存：两条通道互不冲突，本地备份失败不影响局域网手动迁移

## 7. 场景矩阵

| # | 场景 | 期望行为 |
| --- | --- | --- |
| 1 | 首次安装，无备份 | 正常全新启动；授权后开始备份 |
| 2 | 卸载重装，有备份，授权成功 | 自动恢复全部数据并刷新界面；写回一份新备份 |
| 3 | 卸载重装，有备份，拒绝授权 | 全新启动，功能正常；不再自动询问；设置页可重新授权 |
| 4 | 卸载重装，系统「拒绝且不再询问」 | 同 3，设置页入口引导到系统设置 |
| 5 | 应用内「清除数据」后启动（未卸载） | 私有库为空、备份仍在 → 按恢复流程恢复 |
| 6 | 应用内清空全部收藏/历史后卸载重装 | 清空动作已写入空备份 → 重装后保持为空，不复活旧数据 |
| 7 | 本地库非空时升级安装新版本 | 不触发自动恢复，数据不变；启动补写更新备份 |
| 8 | 主备份损坏、`.prev` 完好 | 从 `.prev` 恢复 |
| 9 | 主备份与 `.prev` 都损坏 | 全新启动，不崩溃、不提示 |
| 10 | 备份是未来版本格式（version>1） | 静默放弃恢复，全新启动，不覆盖备份 |
| 11 | 备份文件超大（>2 MB）或 JSON 结构异常 | 同 10 |
| 12 | 写入过程中断电/杀进程 | 按第 3 节中断点表处理；启动清理 `.tmp` |
| 13 | 写入时磁盘满 / 存储只读 | 静默跳过本次写入，保留旧备份 |
| 14 | 使用中权限被系统回收 | 后续写入静默失败；设置页状态变为未授权 |
| 15 | 设备无公共存储（少数盒子） | 自动备份停用，功能不受影响，设置页提示不可用 |
| 16 | 用户手动删除备份文件 | 下次数据变更后重新生成；若要彻底停用需关闭开关或撤销权限 |
| 17 | 用户关闭「本地自动备份」 | 不写、不恢复；已有备份文件保留，重新打开后继续覆盖 |
| 18 | 备份恢复过程中应用被杀 | 下次启动可重新恢复（幂等） |
| 19 | 恢复后立即产生新数据 | 脏标记触发防抖写入，备份反映合并后的数据 |
| 20 | 手机备份导入与本地备份同时发生 | 二者都走 `Library.restore` 与写队列，串行执行，不互相覆盖 |
| 21 | 多用户/访客账户 | 各账户有独立外部存储视图，互不可见；不做跨用户迁移 |
| 22 | 系统时间被修改 | `createdAt` 仅用于排查展示，不参与新旧判断；恢复不看时间 |
| 23 | 备份来自其他设备（用户手动拷贝） | 可恢复；合并语义与手机备份一致 |
| 24 | 恢复时收藏数量达到上限 | 按 `LibraryBackup.merge` 规则截断到 500（本地优先保留，超出部分丢弃），不报错 |

## 8. 兼容与数据规则

- 格式标识固定 `hongguotv.library`，当前 `version=1`
- 同一版本内新增字段：读取端忽略未知字段（现有 `decode` 已按需取键），旧版本 App 读到新备份不会崩溃
- 破坏性变更才提升 `version`；更高版本备份被旧 App 读取时静默放弃（不恢复、不覆盖）
- 合并语义完全复用 `LibraryBackup.merge()`：收藏本地优先、进度取 `updatedAt` 较新者、分组/搜索/稍后看并集截断、`restoreSettings=true` 时设置以备份为准
- 恢复设置只覆盖 `BackupSettings` 白名单字段，主题与跳过标记不受影响

## 9. 隐私与安全

- 备份为明文 JSON，位于公共目录，用户与其他应用可读；内容仅剧集标题/ID/封面地址/进度与播放偏好，不含账号、Cookie、签名密钥或设备标识
- 文件名与格式固定，写入前做与手机备份相同的字段清洗（控制字符、URL 校验、长度限制）
- 设置页在说明文案中明确告知备份位置与内容范围；提供关闭开关与手动删除方式（关闭开关后删除文件即可彻底停用）

## 10. 测试计划

单元测试（`core`，可注入临时目录与假时钟）：

1. 轮换写入：主文件缺失时从 `.prev` 读取；两份都坏返回空
2. 中断模拟：只存在 `.tmp`、只有 `.prev`、主文件为半截 JSON
3. 空库才恢复：库非空时 `restoreChecked` 逻辑不调用恢复
4. 未来版本/超大文件/非法 JSON 静默失败
5. 合并：恢复后收藏去重、进度取新、分组清理、设置覆盖
6. 脏标记：空库启动不写、清空数据后允许写空备份

真机/模拟器验收（API 26、29、30+ 各一台或模拟器）：

7. 正常备份：改动收藏后 5 秒内文件更新且可解码
8. 卸载重装 + 授权：全量恢复
9. 拒绝权限：无异常、不重复弹窗、设置页可手动授权
10. 主文件改坏：从 `.prev` 恢复
11. 关闭开关：不再写入；重新打开后恢复写入
12. 厂商电视「所有文件访问」入口缺失：设置页显示不可用并可走手机备份

## 11. 验收标准

1. 正常使用中产生收藏/进度变更，5 秒内 `/sdcard/hongguotv/hongguotv-backup.json` 更新且内容可解码
2. 卸载重装后首次启动：授权一次 → 收藏、稍后看、进度、历史、搜索、分组、播放/弹幕设置全部恢复
3. 拒绝权限：应用无任何异常，重启不再弹权限；设置入口可手动重新授权
4. 删除备份文件后重装：正常全新启动
5. 主备份文件改坏 + `.prev` 完好：重装后从 `.prev` 恢复
6. 已有数据的应用升级到新版本：不出现自动恢复行为，数据无变化
7. 用户主动清空数据后卸载重装：保持为空，不恢复旧数据
8. 关闭自动备份开关后：不产生新写入，也不触发恢复

## 12. 实施清单

- 新增 `core`/`app` 存储适配与轮换读写（建议独立文件 `LocalBackupStore.kt`，纯 JVM 可测）
- `Library`：`persist()` 后置脏标记并安排 5 秒防抖；`flush()` 检查脏标记；启动补写；恢复入口 `restore()`
- `MainActivity`：首次启动恢复提示与权限申请、设置页「本地备份与恢复」入口与状态展示、恢复后的界面刷新
- `AndroidManifest`：`WRITE_EXTERNAL_STORAGE(maxSdkVersion=28)`、`READ_EXTERNAL_STORAGE(maxSdkVersion=32)`、`MANAGE_EXTERNAL_STORAGE`、`android:hasFragileUserData="true"`
- 私有 prefs 新增：`localBackupEnabled`（默认 true）、`restoreChecked`、`permissionAsked`
