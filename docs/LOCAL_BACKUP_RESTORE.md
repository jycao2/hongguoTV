# 本地备份与自动恢复（遗留需求，未实现）

> 状态：**已批准方案，暂缓实现**（2026-10-18 记录）。实现前无需重新评审，按本文执行即可。

## 背景与目标

用户手动卸载应用后重新安装，希望**不走远程、不手动操作**即可恢复本机数据。现状是所有数据保存在应用私有目录，卸载即清空。

- 恢复范围：收藏、观看进度、历史、搜索记录、收藏分组、播放/弹幕设置
- 不恢复：首页 7 天缓存（重装后自动重新拉取）、主题、按剧设置的片头片尾跳过（与本机绑定，本来就不在备份格式内）

## 系统限制（方案前提）

| 限制 | 结论 |
| --- | --- |
| 应用私有目录 `/sdcard/Android/data/<包名>` 卸载即删 | 不能用作备份位置 |
| 公共目录（`/sdcard/` 下自建目录）文件卸载后保留 | 备份唯一可行的本地位置 |
| 存储权限在卸载时被系统回收 | 重装后首次启动**必须重新授权一次**，「零点击自动恢复」在原生 Android 上不可能，方案上限 = 一次授权点击 |
| `android:hasFragileUserData="true"` | 仅提供系统卸载页「保留应用数据」勾选项，与公共目录方案互补，可顺带添加 |

## 功能需求

### 备份（写）

1. 挂载点：[Library.kt](../kotlin-tv/app/src/main/kotlin/com/hongguotv/nativeapp/Library.kt) 写队列统一出口，两个触发时机：
   - 每次 `persist()` 落盘成功后，**防抖 5 秒**写一次全量备份（连续操作只产生一次写入）
   - `flush()` 生命周期检查点（切后台/退出）时立即写一次
2. 写入在现有串行写队列线程执行；先写 `.tmp` 临时文件再原子替换正式文件，不产生半截文件
3. 序列化复用 core 层 [LibraryBackup.encode()](../kotlin-tv/core/src/main/kotlin/com/hongguotv/core/LibraryBackup.kt)（与手机备份同格式，≤2MB），数据来自 `LibraryIndex.snapshot()`
4. 无权限时静默跳过，不重试、不报错、不提示

### 文件布局（防多份、防损坏）

- 固定目录 `/sdcard/hongguotv/`，固定文件名 `hongguotv-backup.json`，每次整体覆盖，**不累积多份**
- **双文件轮换**：写新文件前把当前正式文件改名为 `hongguotv-backup.prev.json`，写入成功即完成；覆盖瞬间断电也不会丢掉唯一副本
- 恢复时先试主文件，解码失败自动试 `.prev`，两个都坏按全新启动
- 只认固定文件名，用户手动拷入目录的其他文件不受干扰（格式自带 `createdAt` 时间戳可供排查）

### 恢复（读）

1. 触发条件（两个同时满足才执行）：**本地库为空** + **备份文件存在且能正常解码**
2. 重装后首次启动：检测到备份文件存在 → 显示一行说明（「检测到本机备份，授权存储权限后自动恢复收藏与记录」）→ 申请存储权限 → 授权成功即自动导入
3. 导入走现有 `LibraryBackup.decode()` + `Library.restore()`（`restoreSettings=true`），合并语义与手机备份一致
4. 容错：备份缺失/损坏/版本不符均按全新状态启动，不崩溃、不提示
5. 本地库已有数据时**永不自动恢复**，避免覆盖现有数据

### 权限拒绝的处理

- 应用功能完全不受影响（数据在私有目录，无需权限）
- 首次启动仅申请一次；被拒绝后记标记，**之后永不再自动弹权限请求**
- 设置页新增「本地备份与恢复」入口作为手动出口：被拒过的用户可在此重新触发授权（API 30+ 跳系统「所有文件访问」设置页，≤29 走标准运行时权限弹窗），授权成功立即补写一次备份
- 不想要权限的用户仍可使用 0.5.0 的「手机备份与恢复」（局域网扫码手动迁移），两条通道互不冲突

## 技术要点

- Manifest：`WRITE_EXTERNAL_STORAGE`（`maxSdkVersion=29`）+ `MANAGE_EXTERNAL_STORAGE`（API 30+）+ `requestLegacyExternalStorage`（API 29 过渡）+ `android:hasFragileUserData="true"`
- 权限判断：API 30+ 用 `Environment.isExternalStorageManager()`，≤29 用 `ContextCompat.checkSelfPermission(WRITE_EXTERNAL_STORAGE)`
- 备份逻辑只允许追加在 Library 写队列统一出口，不得在 UI 层各自写文件
- 单元测试可覆盖：轮换写入（主文件损坏时回落 `.prev`）、空库才恢复、坏文件静默忽略；恢复合并语义已被现有 `LibraryBackupTest` 覆盖

## 非目标

- 不做远程/云端备份，不做账号体系
- 不做自动定时多版本快照（固定单文件 + 一个轮换副本即为上限）
- 不迁移旧版 RN 应用（`com.hongguotv`）数据

## 验收标准

1. 正常使用中产生收藏/进度变更，5 秒内 `/sdcard/hongguotv/hongguotv-backup.json` 更新且内容可解码
2. 卸载重装后首次启动：授权一次 → 收藏、进度、历史、搜索、分组、设置全部恢复
3. 拒绝权限：应用无任何异常，重启不再弹权限；设置入口可手动重新授权
4. 删除备份文件后重装：正常全新启动
5. 主备份文件改坏 + `.prev` 完好：重装后从 `.prev` 恢复
6. 已有数据的应用升级到新版本：不出现自动恢复行为，数据无变化
