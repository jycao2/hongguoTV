# 红果账号：登录与云端同步

更新日期：2026-11-10。**登录与同步已实现**，本文先讲现状，再保留 2026-09-22 的接入调查作为背景。

## 已实现（现状）

| 能力 | 版本 | 说明 |
| --- | --- | --- |
| 扫码登录红果账号 | 0.25.0 | 走红果官方扫码登录通道；登录后手动同步观看记录到云端 |
| 云端观看记录 | 0.25.0 | 可随时手动刷新红果云端观看记录，只读展示；本机与云端分区展示，云端记录带角标，切换账号不影响本机数据 |
| 云端收藏 | 0.30.x | 收藏页接入红果云端收藏，支持本机 / 云端双区与手动同步 |
| 云端收藏上新 | 0.30.10 起（未发版） | 拉云端书架时自带每剧最新集数，与本地基线 diff 出「已更新 N 集 / 第 X 季已上线 / 新收藏」角标，0 额外请求；集数回退（疑似换季）补拉 1 次详情确认 `newerSeasons`；点进详情重置基线。基线是设备与红果书架间的对账状态，只存本机、不进备份 |
| 手机号验证码登录 | 0.30.10 起（未发版） | 走官方 App passport 移动通道（`security.snssdk.com`），设置 → 红果账号两步输入；网页短信通道被滑块风控拦截（见下文），不做对接 |

实现要点：

- 登录成功后**不重新注册设备**——重注册会破坏会话与设备的绑定关系，导致会话作废（`AccountManager.kt`）。
- 网页短信通道（`/passport/web/send_code/`）实测返回 error 1105 强制滑块验证，滑块轨迹 WASM 加密，**不尝试绕过风控**；触发时 UI 明确降级提示改用扫码登录。
- 手机号登录已于 2026-11-10 用户真机验收通过（收码换会话全流程可用）。

## 背景：2026-09-22 接入调查（当时未实现）

用户目标：用本人抖音账号登录红果，在电视端同步红果收藏、观看历史及续播位置。保持用户只安装 APK、无需自行部署服务。

当时的结论：没有实现红果登录或云端同步。缺少经过验证的红果用户授权、账号映射、收藏和进度读写接口；普通抖音 OAuth 授权不能作为这些权限已获授予的证据。不得将头像或昵称获取成功标记为"红果已登录/已同步"。

- 当时客户端 `ContentRepository` 使用游客内容请求，`Library` 的收藏和进度在本机 SharedPreferences，没有平台账户会话。
- 检查红果官网首页及其直接引用的业务脚本，未找到登录入口或账户同步实现。范围仅限公开资源，不能据此推断平台没有内部或合作接口。
- [抖音 SDK 概述](https://open.douyin.com/platform/resource/docs/develop/summarize/sdk) 描述抖音授权和获取公开用户资料；未找到明确开放红果收藏和观看进度的 scope。
- [抖音网站 OAuth 文档](https://open.douyin.com/platform/resource/docs/develop/permission/web/oauth2) 要求注册开发者配置 ClientKey / ClientSecret；项目未配置该平台注册凭据，不能挪用红果官方 App 的身份和应用密钥来声称已授权。
- 全程未收集用户密码、验证码、Cookie 或令牌。

## 边界与原则（仍然有效）

1. 授权方式必须可安全运行于客户端才能保持纯 APK；服务端必需时另行明确托管方案，不能将密钥塞入 APK。
2. 抖音身份到红果账户的映射及数据授权范围需平台支持，不是加一个 UI 登录按钮即可交付。
3. 接入进度读写前先做本人真实账号只读验证；双端冲突按更新时间与明确的播放会话处理，不能简单取最大集数。
4. 退出、过期、换号需测试；按平台账号隔离缓存，保留并区分既有本地游客记录，避免串号。
5. 应用内局域网二维码（手机输入、快传等）均不是红果登录入口。
